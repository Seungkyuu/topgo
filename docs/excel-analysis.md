# 캐피탈사 엑셀 심층 분석

실제 캐피탈사 견적 엑셀 5종을 분해해 계산 로직 이식 타당성과 구조를 검토한 결과다.
이 문서는 아키텍처(`architecture.md`)와 PRD(`PRD.md`)의 근거가 된다.

## 분석 대상

| 내부 식별 | 금융사·상품 | 규모 | 매크로 |
|---|---|---|---|
| Orix | **오릭스캐피탈** — 운용리스·금융리스·할부·렌트 (올인원) | 3,981 수식 / 7시트 | 없음 |
| Meritz(.xlsm) | **메리츠캐피탈 렌터카** (VBA 저장경로에 명시) | 10,487 수식 / 15시트 | 있음 |
| Rent-B(.xlsm) | 렌터카(탁송·정비 포함, 메리츠 계열 구조) | 14,084 수식 / 15시트 | 있음 |
| AutoLease-CA | 오토리스(운용&금융) CA채널용 | 31,309 수식 / 16시트 | 없음 |

## 핵심 발견

### 1. 복잡도는 "금융 수식"이 아니라 "데이터와 규칙"에 있다
금융 함수(PMT·RATE·IRR·PV)는 파일당 10~40회에 불과하다. 압도적 대다수는:

- **VLOOKUP** (한 파일 최대 27,597회): 차량모델 → 가격 → 잔가율 조회
- **중첩 IF** (한 시트 66,772회): 상품·용도·법인/개인 분기 규칙
- **거대 참조 테이블**: 잔가율표(10,000+ 수식), 차량모델 마스터(1,359×236), 보험요율표, 공채표, 취득세 규칙, 제휴점 정보(83,380행)

즉 월 납입금은 `PMT` 한 줄이 아니라 **취득세·공채·자동차세·보험료·잔존가치·선수금**을 각각 규정대로 조회·계산해 합산하는 긴 사슬의 결과다.
(예: 오릭스 총리스료(월) = 순수리스료 + 자동차세(월) + 보험료(월), 각각이 다시 수십 개 숨은 셀과 잔가표 참조)

### 2. VBA 매크로는 계산 엔진이 아니라 UI 잡일이다
매크로를 디컴파일한 결과, 버튼 클릭 시 옵션 토글(값 −2000/5000 주입), 셀에 수식 한 줄 삽입, 저장(SaveAs) 같은 UI 편의 기능뿐이다. **실제 계산 로직은 100% 워크시트 수식에 있다.** → 이식 시 매크로를 리버스할 필요가 없다.

### 3. 금융사마다 구조가 완전히 다르다
공통 스키마가 없다. 오릭스는 상품별 시트 분리, 메리츠는 입력/출력 2시트+VBA, CA파일은 운용·금융 통합 시트. 셀 주소·시트명·상품 묶음이 제각각이다. → **하나의 파서로 5개를 다 읽을 수 없고**, 금융사×상품별 어댑터가 필요하다.

## 이식 타당성 결론

- 금융 계산 자체는 코드로 정확히 재현 가능(오차 0). 하드한 부분은 **참조 데이터 추출**과 **분기 규칙 이식**이다.
- 세금·공채·자동차세·취득세는 법정 기준이라 **금융사 공통 모듈**로 재사용 가능. 금융사별로 다른 것은 금리·잔가·수수료·상품규칙뿐.
- 사슬이 길수록 이식 오류 확률이 커진다 → **골든 케이스 검증이 필수**(선택 아님).
- 5종 전부 완전 이식은 대규모 작업. **금융사별 대표상품 1개씩**부터 넓혀가되, 첫 조각은 가장 깔끔한 **오릭스 운용리스**로 파이프라인을 검증한다.

## 재현 방법

분석 스크립트는 `openpyxl` / `oletools` 기반이며 다음을 수행했다: 시트·정의된 이름·상태 덤프, 수식/함수 빈도 집계, VBA 디컴파일, 출력 시트 계산 사슬 추적. 원본 파일은 저장소에 포함하지 않는다(개인정보·저작권).
